# Decisions and deviations

Locked decisions in HANDOFF.md section 2 are unchanged. Entries below are deviations or Phase 0 choices, each needing your OK where marked.

## 2026-10-18

1. **Python pinned to 3.14** (`pipeline/.python-version`, `requires-python >=3.14`). Latest stable 3.x uv 0.10.8 lists; 3.15 is alpha. Why: you asked for the latest stable.
2. **TypeScript pinned to ^6.0.3** in `web/`. Why: `svelte-check@4.7.7` peers `typescript ^5 || ^6`; 7.0.2 fails `npm install` without `--legacy-peer-deps`. Revisit when svelte-check supports 7.
3. **PMTiles built with DuckDB's GDAL writer, not tippecanoe.** Why: tippecanoe is not installed on the maintainer's machine and DuckDB spatial's PMTiles driver produced a valid 2.4 MB file. Trade-off: no per-zoom feature dropping. Not a spending change; no extra tools. Keeps the pipeline dependency set at Python + DuckDB.
4. **Parquet partitioned small (per version x scenario x year) and not assumed range-readable on Pages.** Why: measured, DuckDB-WASM does full GETs there (docs/SPIKES.md section 8). Needs no spending change.
5. **Ship only the EH build of DuckDB-WASM** (36 MB) in the spike, not the MVP build (41 MB). Why: repo size; EH is supported by current Chrome, Firefox, Safari. Trade-off: very old browsers fail. **Needs your OK** before Phase 2 (alternative: ship both, +41 MB once; the binary only changes when DuckDB-WASM is upgraded, so git history growth is per-upgrade).
6. **GitHub Pages was enabled via `gh api` and the spike plus ~11 MB of spike data were pushed to `main`.** Why: HANDOFF Phase 0 requires live range tests. `docs/spike.html`, `docs/assets/` and `docs/data/_spike/` are throwaway; remove in Phase 2.
7. **Raw-file naming/layout in `data-raw/`:** `faf5/ faf6/ history/ zones/ network/ county/` plus gitignored scratch `data-raw/x/` (extracted files, profiling output). Only `manifest.json` is tracked. The manifest records the 15 files fetched (the 2050 network/CSV extracted via range reads from the 2050 zip is not listed; it lives in `data-raw/network/x50/`).
8. **`utah.yml` bbox kept** at `[-114.06, 36.99, -109.04, 42.01]` after verification against the real zone geometry.

## Decided 2026-10-18 (your call on the Phase 0 proposals: "go with your recommendations")

- **Zone anchor points:** population-weighted mean of the Census 2020 county centers of population that fall inside each zone (new public input: `CenPop2020_Mean_CO.txt`, in `config/sources.yml`, recorded in the manifest). If that point falls outside the zone polygon, the most populous county center inside is used; if no county center falls inside, `ST_PointOnSurface`. The method is stored per zone in `dim_zone.anchor_method`. Result: FAF5 123 of 132 zones population-weighted, 9 fell back; FAF6 124 of 134, 10 fell back. The state's Salt Lake zone now anchors in the Salt Lake Valley instead of the western desert.
- **Network centroid connectors (`Class` 50):** kept in the data (`road_class` = 50, flagged in the dictionary caveat); the Phase 2 map hides them by default. Nothing is filtered out in the pipeline.
- **Zero-flow rows:** dropped when every measure is zero for that (key, year); NULL always means "not published" (e.g. FAF5 `value_current_musd` for 2017 and forecasts, FAF6 `tmiles_m`), never 0.
- **DuckDB-WASM:** EH build only (36 MB), as recommended. Takes effect in Phase 2; the spike already does this.

## Phase 1 choices and deviations

1. **Canonical column names** (all documented in `dictionary.parquet`): `tons_kt` (thousand tons), `value_const_musd`, `value_current_musd`, `tmiles_m`; zone fields `dms_orig`/`dms_dest` (regional) and `dms_orig_st`/`dms_dest_st` (state database); `dist_band` is kept for FAF5 (NULL column absent in FAF6 files). The dictionary table uses `table_name` and `column_name` because `table`/`column` are awkward SQL names.
2. **Output layout:** `docs/data/<faf5|faf6>/flows/<scenario>/<year>.parquet` (regional), `.../state_flows/<scenario>/<year>.parquet`, `docs/data/network/{<state-slug>_network.pmtiles, link_attrs.parquet, link_flows/<year>.parquet}`, `docs/data/geo/{faf5_zones,faf6_zones}.geojson, zone_centroids.json, foreign_regions.json`, `docs/data/meta/{state.json, versions.json, dictionary.parquet, dim_*.parquet}`. The PMTiles file name comes from the state config file stem, not a literal.
3. **Link flows are long:** `link_id, year, truck_type (all|su|cu), market (total|domestic|import|export), commodity_group (12 FHWA groups + all), ab/ba/tot tons_k and trips_day`. About 2 MB per model year for the state's clip.
4. **Clip buffer is computed in a local azimuthal equidistant projection** centred on the state polygon (not a US-wide CRS), so it also works for Alaska/Hawaii-style states. The clip must contain every link tagged with the state FIPS or the build fails.
5. **`build --scaffold-map` takes `SCHEMA CSV NEW_SCHEMA`** (copy an existing column map for a new release's header), not `<product> <version>` as written in HANDOFF; it needs the new file path anyway.
6. **DuckDB extensions `spatial` and `excel` are installed from DuckDB's extension repository on first use** (a network dependency per machine; no cost).
7. **`data_version` classes live in `config/sources.yml`.** A year present in a file but not classified there fails the build. For FAF6 I set `base: [2022]` and `forecast_from: 2023` as a placeholder policy; revisit when BTS publishes FAF6 annual years.
8. **Hi/Lo scenarios, state history and county product are not built yet** (Phases 3 and 4). The data model already carries `scenario`; Phase 0 profiles in `docs/SPIKES.md`.
9. **Tests** live in `pipeline/tests` (fixtures only, a fictional state `Testland`, fips 99). Run `uv run pytest` from `pipeline/`. A test also asserts the real repo contains no state literal.

## Phase 2 choices and deviations

1. **Flow views.** All four views (Total, Domestic, Import, Export) filter on `trade_type` and define direction on the domestic leg (`dms_orig` to `dms_dest`). Arc endpoints: Total and Domestic use the domestic leg; **Import draws foreign region to U.S. destination** and **Export draws U.S. origin to foreign region**, so foreign regions appear as (schematic) locations. The entry/exit zone is not an arc endpoint in those views; it will be added to the detail panel in a later phase. Because rows are kept when the entry zone is in the state, an import arc can end outside the state; that is the data, and the view hint says so.
2. **Commodity presets are the 12 FHWA assignment groups** (SCTG membership from the FHWA data dictionary), not invented groupings such as "Energy" or "Manufactured". A preset is a group checkbox; selection is a plain list of SCTG codes (empty means all).
3. **Top-N and the threshold are applied in SQL**, so "showing X of Y flows (Z% of total)" is exact and a zone selection re-ranks that zone's own flows. Selecting a zone isolates flows involving it (it is not just a highlight).
4. **First paint** uses `headline_flows.json` (60 largest domestic-leg flows, default year) only when the URL is at its defaults; DuckDB-WASM then replaces it. Measured on the local build in headless Chromium: first arcs about 0.3 s, DuckDB results about 1.7 s. Parquet is fetched whole (Pages behavior, docs/SPIKES.md section 8).
5. **Measure availability is discovered from the data** (NULL sums), not hardcoded: ton-miles are disabled for FAF6.0, current dollars for years that do not publish them. If a shared URL asks for an unavailable measure the app falls back to tons or constant dollars and says so.
6. **Network layer:** PMTiles with `promoteId: id`; volumes joined by feature-state from the link-flow Parquet (trips per day, both directions, `commodity_group = all`); links without a flow row are muted grey; centroid connectors hidden by default (toggle). The FAF5 provenance badge is always visible while the layer is on, including when FAF6 flows are shown.
7. **URL state** uses short query keys (`v, y, view, dir, m, usd, com, mode, top, min, sel, l, ny, nt, nm, cc, bm, theme, c`), writes only non-default values, and ignores invalid values instead of failing. The map camera is stored as `c=lon,lat,zoom`.
8. **Mode colors in the KPI bar** use a fixed 8-color palette; the bar is paired with the text shares and an accessible label, so color is never the only channel. Arc color is not tied to mode in Phase 2 (width carries the measure).
9. **Test hook:** `window.__faf` (the controller) is exposed only when `localStorage['faf-debug']` is set, for browser tests.
10. **Spike removed:** `docs/spike.html`, `docs/assets` (old), `docs/data/_spike` and `web/src/spike` are deleted. `npm run build` first deletes the previous hashed assets in `docs/` (`scripts/clean.mjs`), then builds `web/index.html` into `docs/`.
11. **Not in Phase 2 (by plan):** charts, scenario switching (High/Low shown disabled), compare mode, table/CSV export, state summary, Methodology page, county mode.

## Phase 3 choices and deviations

1. **High and Low are ingested from the FAF5.7.1 Hi/Lo files** (regional 426 MB, state 203 MB; added to `config/sources.yml` and the manifest). Each Hi/Lo file is the full file plus `<tons|value>_<YYYY>_<low|high>` columns for the forecast years, so the schema guard gained scenario-column patterns. They are written as `flows/<high|low>/<year>.parquet` and `state_flows/...`, with `scenario` and `data_version = forecast`. **High/Low publish tons and value only**: `value_current_musd` and `tmiles_m` are NULL for them, and the UI disables ton-miles and current dollars there.
2. **New build checks:** (a) the plain mid-range columns inside each Hi/Lo file must equal the mid-range files already written (they do, to 1e-6, for all 13 years in the regional file); (b) High/Low regional-to-state reconciliation, same as mid; (c) a report-only check that low <= mid <= high in aggregate (no violations).
3. **Scenario availability comes from `versions.json`** (`scenarios` per product). Choosing High or Low while on an annual year moves to the first forecast year and says so. FAF6.0 shows the scenario radios disabled.
4. **Trend and compare charts read all years at once:** the first time the Trends or Compare tab opens, all of a version's Parquet files (about 11 MB for FAF5.7.1 including High/Low) are loaded into one in-memory DuckDB table, then every chart query is local. The other version's table is loaded only when the overlay is switched on. No pre-aggregated cube is shipped, because compare-by-zone needs the detail anyway.
5. **Forecast boundary and preliminary markers are computed from the data's `data_version`**, not hardcoded years: a vertical line at the midpoint between the last annual estimate and the first forecast, a "preliminary" line at the first preliminary year, and an annotation when the release publishes nothing in between ("no estimates 2025-2029"). Marker shapes (diamond benchmark, filled circle final, hollow circle preliminary, triangle forecast) plus a text key carry the status, so color is not the only channel.
6. **FAF5 and FAF6 are never one line.** The overlay draws the other version as a separate grey, dotted series with square markers and prints a benchmark-break notice built from the versions' benchmark years. FAF6.0 alone shows a "publishes 2022 only, no trend yet" note.
7. **Compare mode** takes up to six zones or six commodities within one version, mid-range scenario, all years. A zone's series is the flows involving it (per the current view's endpoints); comparing commodities ignores the commodity filter. A single item is drawn but flagged.
8. **Table and CSV:** grouped by the ticked columns (origin, destination, commodity, domestic mode, trade type); the page shows the 200 largest rows and the CSV has every row (cap 250,000). The CSV puts version, scenario, year, data status, flow view, direction and dollar basis on every row, carries both codes and labels, uses unit-bearing measure headers (`tons_thousand`, `value_constant_million_usd`, `value_current_million_usd`, `ton_miles_million`), and leaves NULL cells empty (never 0).
9. **State summary is the Summary tab** (within/inbound/outbound shares, top partners, top commodities, mode mix, commodity-by-mode heat map) rather than a separate page. Every chart has a text "Data table" alternative.
10. **Chart palette:** Okabe-Ito (colorblind-safe), shared with the KPI mode bar. Axis numbers use plain thousands separators in the measure's raw unit ("20,000 thousand tons") instead of SI suffixes, which would read as "20k thousand tons".
11. **Still not done:** state history 1997-2012 and the county product (Phase 4); Methodology page, README completion, CONTRIBUTING, LICENSE (Phase 5).

## Phase 4 choices and deviations

1. **History is a fourth data product, not a FAF version.** `history` (FAF5.7.1 reprocessed state history) is built with the same flow machinery (state level only, schema guard `faf5_history_state`, `data_version = historical`, 2017 dollars per the FAF5 User Guide) into `docs/data/history/state_flows/mid/<year>.parquet` (4 files, 1 MB). `versions.json` gains a `kind` per product (`flows`, `history`, `county`); the version switcher lists only flows and county products. The UI labels it "Historical state-level series, FAF5 reprocessed", says the years are five-year snapshots rather than annual, and shows it as its own tab. It is never drawn as one line with the annual series: the optional FAF5 annual overlay is a separate series behind a divider.
2. **The county product is a third selectable "version"** (`county-exp`, "County estimates (experimental)") rather than a separate mode, so every existing control, chart, table and CSV works on it unchanged. To make that possible its flows are written in the same column layout as the FAF flow tables: `dms_orig`/`dms_dest` hold 5-character county FIPS or, for the outside-zone side, a 3-character FAF5 zone id; `sctg2` holds the county product's five commodity group codes; `dms_mode` holds its own mode codes (2, 3, 5, 6, 11); `value_*` and `tmiles_m` are NULL (tons only), `faf_version` = `county-exp`, `data_version` = `experimental`, plus `orig_zone`, `dest_zone` and `table_kind` (c2c, c2f, f2c). The UI therefore needed only relaxed id/code patterns, a Value-availability check, per-version commodity groups and the stamps below.
3. **Only state-touching rows are kept from the county zip's tables:** county-to-county where either county is in the state, county-to-FAF where the origin county is, FAF-to-county where the destination county is. The fourth table (zone to zone among the other zones) cannot touch the state and is skipped. Nothing is double counted (verified: domestic tons by mode reproduce FAF5.7.1 2022 exactly; `validate` fails if any mode is more than 1% apart).
4. **Adjacent states are derived from the data** (counties present in the county-to-county table), not typed: for the configured state they are 04, 08, 16, 32, 35 and 56. The zip name is `<fips> - <name>.zip`; a state whose BTS name differs can set `overrides.county_zip_name`.
5. **County geography:** Census 2022 cartographic boundary counties (1:500,000; new public input, in `sources.yml` and the manifest), simplified like the zone shapes, for the state plus adjacent states (225 counties, 0.25 MB). Arc anchors are the Census 2020 county centers of population already used for zones; outside FAF zones reuse the FAF5 zone anchors.
6. **Factors:** the 8 factor files are ingested to `county/factors.parquet` (4,172 rows) for the state's and the adjacent states' zones, with zone ids and county FIPS zero-padded (the source drops leading zeros) and a build check that each zone/mode group/commodity group sums to 1. The UI does not use them yet; they are published so users can rebuild county flows from FAF zone flows.
7. **Experimental stamps:** a banner over the map, the footer, the version button label and hint all say EXPERIMENTAL, FAF5.6.1-based, 2022, tons only, not comparable with FAF numbers. Value, ton-miles, scenarios, trends, compare and history are unavailable (disabled or hidden) in that version. The benchmark-break overlay never offers the county product as "the other version".
8. **Filters do not carry across versions:** switching version clears commodity and mode filters, since their codes differ.
9. **The county total is not FAF6.** `validate` prints, report-only, the state's 2022 domestic-touching tons for the county product (217,325 kt), FAF5.7.1 (217,325) and FAF6.0 (329,980). They are never merged.
10. **Default version** is the first FAF release by product key (FAF5.7.1); no version string is hardcoded in the app.
11. **Still open:** FAF6 dollar year; the cause of the small import/export gap between the county product and FAF5.7.1; a map view of the county factors.

## Phase 5 choices and deviations

1. **License: MIT** for the code (HANDOFF left MIT or Apache-2.0 to the maintainer). The copyright line reads "ar-puuk and the Freight Explorer contributors" (the GitHub handle, not a personal name). **Needs your OK or a change**: it is one file (`LICENSE`) plus the `license` fields in `web/package.json` and `pipeline/pyproject.toml`. Data stays U.S. public data with attribution (README, methodology page).
2. **The methodology page is a second page of the same site** (`docs/methodology.html`), built by a second `vite build --mode methodology`. A single multi-page Vite build was tried first and **broke the map**: the combined chunk layout made the MapLibre and deck.gl WebGL contexts get lost at load (the map never finished loading its style). The map's bundle is therefore built alone, exactly as before. The page reads `meta/versions.json` and `state.json` at load, so the sources table (release, years by status, source file sizes and SHA-256 prefixes) is always what is actually deployed.
3. **Methodology text only states what was verified.** FAF5 dollars (2017) are verified against the FAF5 User Guide; the FAF6 dollar year (2022) is marked as taken from the release notes; BTS pages return 403 to scripts, so the status of years comes from the BTS version history read earlier (a Wayback snapshot plus the FAF5 landing page) and is cited as the BTS version history. Limits of FAF are quoted from the BTS FAQ as read on 2026-10-18.
4. **Basemap outage tolerance.** If the basemap style fails or takes more than 10 seconds, the map switches to a plain background (flows, zones and network keep working) and says so; choosing a basemap tries again. Found by blocking the basemap host in a test: before the fix, the app silently stopped before starting the query engine, because map operations ran before any style existed. Two details learned the hard way: the deck.gl overlay must receive its first props before the style loads (holding them back stalls the map), but a failure then (no style, so no projection) must be tolerated and the layers pushed again on the next `style.load`; and MapLibre's `error` event also fires for single sprite/glyph/tile failures, so only a style that never loads triggers the fallback (an 'error' before `style.load` or a 10 s timeout).
5. **Content-security policy** (a `<meta>` tag, since Pages sets no headers): the page may load only its own files, OpenFreeMap (styles, tiles, glyphs, sprites), `blob:` workers and WebAssembly. Verified with zero violations across the map, charts, network, basemap switching, county mode, CSV download and the methodology page. Test scripts that inject axe-core as an inline script are (correctly) blocked; they use Playwright's init-script injection instead.
6. **Accessibility pass.** Added: skip links, landmark roles, a visually hidden list of the 10 largest flows that the map element is described by, a zone/county picker (a keyboard alternative to clicking the map), `Escape` to close details, a visible focus ring on MapLibre's own controls, deck.gl's canvas removed from the tab order, reduced-motion handling for map animation, 24 px minimum targets, and an off-screen mobile filter sheet that is now removed from the tab order (it was previously focusable while hidden). axe-core with WCAG 2.2 AA (including target size) reports 0 violations on 38 view/theme/device combinations; keyboard and 320 px reflow checks pass. Not done: testing with a real screen reader or real devices.
7. **Performance pass.** Measured on the live site (headless Chromium, median of 3): first arcs 0.56 s, query engine ready 2.0 s, largest contentful paint 0.37 s; 1.1 MB gzipped JavaScript for first paint; DuckDB-WASM (34 MB, 8.3 MB gzipped) after first paint. The chart code (Observable Plot and the tab components) is now loaded on demand (0.24 MB). The remaining first-paint JavaScript is the map stack (MapLibre, deck.gl, flowmap.gl, DuckDB-WASM's JavaScript), all needed for the first view, so nothing more was split. `rel=preconnect` to the basemap host, an inline favicon and a `noscript` message were added.
8. **Second-state smoke run (Colorado)** in a scratch clone with the raw files hard-linked: `update` 1 min 32 s with files on disk, validation passed after one fix (the FIPS literal check no longer applies to YAML code tables; Colorado's FIPS 08 equals SCTG 08), county estimates conserve FAF5.7.1 domestic tons by mode (328,562 kt), 2 zones, 64 counties plus 7 adjacent states, network clip 8,980 links (5,871 with flow), the app loaded and showed Colorado data in all three versions. Documented in the README without promising support.
9. **Test hook kept:** `window.__faf` is exposed only when `localStorage['faf-debug']` is set.
10. **Left open:** FAF6 dollar year verification; the small import/export gap in the county product; Firefox, Safari, real-GPU and real-phone testing; a screen-reader test; Alaska, Hawaii and DC (unusual zone structures) untried.
